# Engineering Guidelines & Production Rules

This repository contains the ACME HR Salary Management Platform. All AI coding agents, developers, and automated tools MUST strictly adhere to these production-grade rules during code generation, refactoring, testing, and git operations.

---

## 1. Architectural Principles

1. **Clean Layered Architecture (Backend)**
   - Strict separation of concerns: `Controller -> Service -> Repository -> Entity`.
   - Controllers MUST NOT contain business logic or direct database calls.
   - Services MUST NOT return JPA Entities directly to the API layer. Always map to and from DTOs (`RequestDTO`, `ResponseDTO`).
   - Controllers MUST use `@Valid` on request bodies and return standardized `ResponseEntity<T>` envelopes.

2. **Component Separation & Clean Code (Frontend)**
   - Separate UI presentation components from stateful custom hooks and data fetching logic.
   - Use strict TypeScript interfaces for all API response payloads and props. Never use `any`.

3. **Data Integrity & Schema Mapping**
   - JPA Entities must map 1:1 with the MySQL schema defined in `acme_salary_db`.
   - Never alter the MySQL table schemas without updating both Flyway/Liquibase migrations and JPA mappings.
   - The field `compensation.total_company_cost` is a stored calculated column in MySQL. Mark it as `@Column(insertable = false, updatable = false)` in JPA to prevent ORM write overrides.

---

## 2. Java & Spring Boot Standards

1. **Java Version & Language Features**
   - Java 17 baseline. Use Java `record` types for immutable DTOs wherever applicable.
   - Prefer constructor injection over field injection (`@Autowired` on fields is strictly FORBIDDEN).

2. **Performance & Scalability (10,000 Records Rule)**
   - Never execute $N+1$ queries. Use JPQL `@EntityGraph` or explicit `JOIN FETCH` when fetching related associations.
   - Aggregations (e.g., total CTC spend, average salary, median) MUST be computed directly at the database layer using SQL native or JPQL queries—NEVER pull 10,000 entities into Java memory to calculate averages.
   - Seeding 10,000 records MUST use JDBC batch processing (`saveAll` with `spring.jpa.properties.hibernate.jdbc.batch_size=500`) to execute within 5 seconds.

3. **Error Handling & Logging**
   - Do NOT capture exceptions with empty `catch` blocks or `printStackTrace()`.
   - Use `@RestControllerAdvice` (`GlobalExceptionHandler`) to intercept all application exceptions.
   - Return standard RFC 7807 problem details or uniform JSON error payloads:
     ```json
     {
       "timestamp": "2026-09-23T13:15:00Z",
       "status": 404,
       "error": "Not Found",
       "message": "Employee with ID 1042 not found",
       "path": "/api/v1/employees/1042"
     }
     ```

4. **Security & CORS Rules**
   - Standardize on Spring Security 6 stateless HTTP Basic Auth or Bearer tokens.
   - Explicitly define CORS origins (`http://localhost:3000` for frontend dev).
   - Never expose raw database credentials or secrets in code files. Use `application.properties` with environment variable overrides.

---

## 3. Testing Requirements

1. **Coverage Expectations**
   - All core business logic in Service classes MUST have unit test coverage using JUnit 5 and Mockito.
   - Controllers MUST be verified using `@WebMvcTest` asserting HTTP status codes (200, 201, 400, 401, 404).

2. **Deterministic & Isolated Tests**
   - Tests MUST NOT depend on an active local MySQL instance. Use H2 in-memory database (`@DataJpaTest`) or Mockito mocks for test isolation.
   - Every test MUST cover at least 3 scenarios:
     1. **Happy Path:** Valid input yields expected 200/201 result.
     2. **Edge Case:** Boundary conditions (e.g., empty dataset, 0 headcount, median on even vs. odd records).
     3. **Worst Case / Failure:** Non-existent IDs, invalid inputs, or duplicate resources throwing expected exceptions.

---

## 4. Git & Commit Workflow

1. **Atomic Commits Only**
   - Never dump an entire multi-layered feature into a single massive commit.
   - Commit incrementally using the Model Context Protocol (`git` MCP) after completing each distinct milestone.

2. **Conventional Commit Syntax**
   All commit messages MUST follow the Conventional Commits format:
   - `feat(scope): ...` for new features
   - `fix(scope): ...` for bug fixes
   - `test(scope): ...` for adding or updating unit tests
   - `docs(scope): ...` for PRDs, architecture notes, or rules

3. **Required Commit Evolution Order**
   - **Commit 1:** `docs: add requirements document and rules.md`
   - **Commit 2:** `feat(config): setup dependencies, application.properties, and security config`
   - **Commit 3:** `feat(domain): implement JPA entities and DTO records`
   - **Commit 4:** `feat(repository): add Spring Data repositories and native aggregation queries`
   - **Commit 5:** `feat(service): implement EmployeeService and batch SeederService`
   - **Commit 6:** `feat(analytics): implement AnalyticsService for CTC, median, and departmental breakdowns`
   - **Commit 7:** `feat(controller): expose REST controllers with global exception handling`
   - **Commit 8:** `test: add unit tests for services, controllers, and exception scenarios`

## 2. Angular 15 & Frontend Production Rules

1. **Architecture & Framework Standards**
   - **Framework Baseline:** Angular 15.0.x with TypeScript 4.8.
   - **Component Architecture:** Use **Standalone Components** (`standalone: true` on `@Component`). Do NOT generate `NgModule` unless necessary.
   - **State Management & Reactivity:** Angular 15 does NOT support Signals. Use **RxJS Observables** (`BehaviorSubject`, `Subject`, `pipe()`) for reactive state management.
   - **Template Subscription:** Always unwraps Observables in templates using the `async` pipe (`*ngIf="data$ | async as data"`). Avoid explicit `.subscribe()` calls in component classes to prevent memory leaks.
   - **Strict Typing:** TypeScript strict mode enabled. Define strict interfaces for all API DTO payloads under `src/app/core/models/`.

2. **UI Design & UX Standards**
   - **Design System:** Utility-first styling via **Tailwind CSS v3** (`tailwindcss@^3.3.0`, `postcss`, `autoprefixer`) and **PrimeNG v15** (`primeng@^15.0.0`).
   - **Color Palette:** Modern, executive glassmorphic dark/light palette (Slate/Zinc neutral shades, Indigo accent colors).
   - **Map Component:** Use **Leaflet.js** (`leaflet`, `@types/leaflet`) for interactive world map rendering with custom HTML markers and dialog popups.

3. **Performance & Optimization**
   - Enforce `changeDetection: ChangeDetectionStrategy.OnPush` across all components.
   - Implement debouncing (`debounceTime(300)`) on search inputs before dispatching backend requests.
   - Lazy load routes using `loadComponent: () => import(...)`.

4. **Frontend Commit Workflow**
   - `feat(frontend): setup Angular 15 standalone structure, Tailwind CSS, PrimeNG, and Leaflet`
   - `feat(frontend-core): create DTO interfaces, HttpClient services, and HTTP Basic Auth interceptor`
   - `feat(frontend-map): build Home page with interactive Leaflet world map & employee callouts`
   - `feat(frontend-db): build Employee Directory with paginated data grid, global search, and dynamic filters`
   - `feat(frontend-analytics): add HR analytics charts for salary distribution and regional spend`
   - `style(frontend): polish layout with glassmorphic cards, animations, and responsive styles`
